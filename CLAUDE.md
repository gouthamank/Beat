# Beat

Music player for Mac, iPad and iPhone on top of the music you already have: the Music app's library on the Mac, songs synced to the device on iOS. It reads the library read-only, shows album art, and plays local files itself. The headline feature is a **sidebar of folders and pages**: each page holds elements, and each element owns a **smart filter** (Filter → Sort → Limit) plus its own appearance. Liquid Glass on macOS/iOS 26, frosted materials on macOS 15.

See `ARCHITECTURE.md` for how the pieces fit together (including the platform split), and `TESTING.md` for the test suites and their plan.

## Hard rules
- **Never write to the Music library.** Reading goes through `iTunesLibrary.framework` (Mac) and MediaPlayer (iOS). Beat's own plays and skips go to `PlayHistoryStore` (`Application Support/Beat/history.json`), never to Music.
- **Liquid Glass branching lives only in `Beat/DesignSystem/Glass.swift`** (`beatGlass(in:)`, `beatGlassButtonStyle()`, `BeatGlassContainer`); no `#available(macOS 26, *)` in views. The Mac target is macOS 15.0 and the dev machine runs 15.x, so every glass call needs a material fallback.
- **Online features are opt-in only.** Lyrics (`lyrics.online`), Discogs artist info (`artistInfo.online` plus the user's token in the Keychain) and Last.fm (`lastfm.enabled`, session in the Keychain) are off by default; off, Beat makes no network requests. Lyrics are never written back to files or Music.
- **No secrets in the repo.** The Last.fm key and secret and the iOS team ID come from the git-ignored `Config/Secrets.xcconfig` (included by `Config/Beat.xcconfig`). User credentials live in the Keychain.
- **Local, DRM-free files only.** Streaming and cloud-only tracks are out of scope; tracks without a playable file are skipped at load.

## Build and test
The Xcode project is generated by XcodeGen and not checked in: edit `project.yml`, never the `.xcodeproj`. The user builds; Claude never runs `xcodebuild` or `xcodegen` (see Working agreements). Claude may type-check with `swiftc -typecheck` against an SDK.

- **Make:** a bare `make` lists every target. `make install`, `make sim`, `make test` and `make snapshot-record` show a menu in a terminal; through Claude Code's `!` prompt there's no terminal, so give the choice up front (`make install on=mac`, `on=ios`; `sim on=ipad|iphone`; `test on=mac|ios|mac-ui|ios-ui|all`; `snapshot-record on=mac|ios|mac-ui`) or run the target it leads to: `make mac-install`, `mac-build`, `mac-test`, `mac-test-record`, `mac-test-ui`, `mac-test-ui-record`, `mac-test-run-fixtures` (KEEP=1 to reopen as left), `ios-install` (device), `ios-sim-ipad`, `ios-sim-iphone`, `ios-test`, `ios-test-record`, `ios-test-ui`; `make clean`. See `TESTING.md`. After adding or removing files, `xcodegen generate` (the make targets run it).
- Requires Xcode 26.x (Swift 6.2, strict concurrency). The real library is large (~20k songs, ~3k albums): keep main-actor work cheap; evaluate and decode off it.
- Mac signing: a self-signed "Beat Local Signing" certificate in the login keychain, so Media & Apple Music and Keychain permissions survive rebuilds (ad-hoc signing re-prompted every build). Recreate it on a new Mac (Keychain Access ▸ Certificate Assistant ▸ Create a Certificate, Code Signing).
- App icon PNGs are generated: edit `Design/AppIcon/render.swift` (keep `AppIcon.svg` in sync), run `swift Design/AppIcon/render.swift`. A stale Dock icon is macOS's cache: `lsregister -f` the built app, quit Beat, `killall Dock`.
- **Platform code:** `Beat/Platform/macOS/` and `Beat/Platform/iOS/` (each target excludes the other) hold same-named files defining the same names (`Platform+*`, `Window+*`, `BeatApp+*`, `SettingsView+*`, `ElementEditor+*`, `FrameProbe`, `BarLayers`, …). Never name AppKit or UIKit types in shared files. Split a difference into those files when it's a self-contained feature or more than ~10 lines; a one-line difference stays an inline `#if os(macOS)`.
- **Phone widths** key off `\.compactLayout` (iOS horizontal size class, set in `platformWindow`; always false on the Mac, so Mac layouts never change), with `\.pageInset` for margins and `sheetSize(width:height:)` for sheets. Switch layouts with one `AnyLayout`, not an if/else, so probed children keep their identity; never give shared views fixed Mac widths without a compact alternative.
- The Simulator has no music library: drag audio files onto it and save them to Files > On My iPad/iPhone > Beat > Music.

## Gotchas (learned the hard way)
**Navigation and window**
- **Pushed `NavigationStack` pages cover overlays on the stack.** So the now-playing bar is one `WindowNowPlayingBar` overlay on the split view, placed over the page column from `navigator.detailColumnFrame` (measured by `DetailColumnReader`). Pages only apply `.nowPlayingBarSpace()`, on the root page and every `navigationDestination`. Don't move the bar onto the stack or the pages.
- **Pushed pages need an opaque background** (`RootView` puts the window background behind every `navigationDestination`); otherwise a popped page showed through grids that draw none.
- **Navigation goes through `AppNavigator`:** open albums, artists and genres only with `openAlbum/openArtist/openGenre` (never `NavigationLink(value:)` or `path.append`), and change `path` once per navigation. Details nest in the page you started from; a route already in the trail is returned to (`opening(_:on:)`). Each sidebar page keeps its path, search and scroll. Back (⌘[, `SwipeBackMonitor`, `SidebarReclickMonitor`) goes through `goBack()`/`path`; `path`'s didSet starts the cover's return flight.
- **Stacks write back on teardown:** a stack torn down after `.id(selection)` changes clears its path; `pathBinding(for:)` ignores writes from a stack whose item isn't selected.
- **The Mac window's minimum width goes on the page column, not the root** (`pageColumnMinWidth`, 680, also on every `navigationDestination`). On the root it cut the sidebar's expand animation short; missing from pushed pages, an album page let the window shrink below the page underneath.
- **The sidebar's minimum width is its ideal width (220).** SwiftUI computes the window's minimum at launch from the sidebar's ideal width but while resizing from its current width; with a narrower minimum, a window shrunk to its smallest reopened up to 39 points wider (caught by `WindowUITests`).
- **The window's root content type must be stable.** SwiftUI saves the window's frame and split under a key made from the content's full type name; a `private` modifier type in that chain (`MacWindow`) gets a per-build address in its name, so the window never got its size back. Keep types used around `RootView` in `BeatApp` internal.
- **SwiftUI can take a background AppKit view out of the window and never put it back.** At launch `DetailColumnReader`'s view was removed during a layout pass (`DisplayList.ViewUpdater` → `removeFromSuperview`), so the bar stopped following resizes. It came and went with unrelated layout details (where `preferredColorScheme` sat, Debug vs Release), so `DetailColumnView` remembers its split-view pane and measures that once detached; measuring views must not depend on staying attached. Debug builds print to the console when this happens (Beat's only console output): "…measuring the split-view pane instead" is the fallback working, "…no split-view pane found" means it's broken.
- **`preferredColorScheme(nil)` doesn't restore the system appearance** on macOS once given a scheme. `windowAppearance()` passes the cover's scheme or the system's (`AppleInterfaceStyle`, updated on `AppleInterfaceThemeChangedNotification`), never nil.
- **Album and artist pages put back and title in the toolbar** (`coverPageToolbar`), with its background hidden and `CoverPageTopBar` drawn under it. Toolbar items get the cover's scheme on the items themselves (on the toolbar, it leaked into the grid's search field). To fill a safe-area strip, use a zero-height view whose *background* ignores the safe area.

**Sidebar and lists**
- **Sidebar tree:** folders and pages mix freely at any level; only pages are leaves. Don't assume structure.
- **Selectable `List` rows on macOS stay plain:** `.draggable`, `.dropDestination` or `.popover` on a tagged row swallows the click. Use `.itemProvider`, drop targets only on folders, popovers from the list level; `.tag` last.
- **No drop insertion in nested sidebar levels** (`ForEach.dropDestination` in nested `DisclosureGroup`s traps): the tree is one flat `ForEach` (`SidebarRow.visible`), and moves run in a `Task` after the drop.
- **Editable lists bind rows by id** (`ForEach(array) { … $array.element(item) }`, `Binding.element(_:)`), not `ForEach($array)`: a deleted row still animating out wrote through a stale index and trapped.
- **`Table` cells don't inherit `@Observable` environment objects** on macOS (AppKit-hosted); reading one traps. Read stores, and `\.playbackAccent`, in the parent and pass them in.
- **Library ▸ Songs on the Mac is an AppKit `NSTableView`** (`AlbumSongsTable`): a `LazyVStack` of ~3k album blocks was too slow. Rows from `AlbumSongsLayout`; covers are a small reused pool of hosted `CoverBlock`s behind on-screen rows; `SongRowView.hitTest` passes cover clicks through. No per-row SwiftUI hover or gestures.
- **Keyboard grids** (`KeyboardGrid.swift`): a collection is one Tab stop (`.keyboardGrid`), items use `.keyboardGridItem(i)` and read `\.gridItem`; tiles' buttons are `.focusable(false)`. Apply it outside `.remembersScroll`/`.tracksScrolling`, and pass `id:` unless items are identified by position (else stale tiles after a search).

**Transitions and drawing**
- **Cross-hierarchy transitions** (cover zoom, Now Playing morph) measure views with `FrameProbe` in window coordinates and draw in an overlay on the split view: `matchedGeometryEffect` and `.global` don't reach across macOS's separately hosted columns and pushed pages.
- **A `FrameProbe` on a view that swaps its content after appearing is released and never rebuilt.** `ArtistArtwork` keeps one fixed outer view and swaps only inside its overlay; never put a probed view's branches in a `Group`.
- **No SwiftUI `.shadow` or live `.blur` on anything that scrolls or animates** (redrawn every frame; the biggest cost on album pages). Use `ShapeShadow` (`Glass.swift`); render big blurs once (`BackdropImages`); run constant animations on Core Animation layers (`PlayingIndicator`).
- **Cover colours have one owner, `CoverTint`** (`navigator.coverTint`), derived from `path` after a short settle. Everything coloured by a cover reads `coverTint.current`; views never publish or clear colours in `onAppear`/`onDisappear` (that raced).
- **Playback colour is `\.playbackAccent`, never `.accentColor`** (progress, playing markers, active playback controls); everything else keeps the system accent.
- **`$appStorage.animation(_:)` doesn't animate:** use `.animation(_:value:)` keyed on the setting. A button that toggles an `@AppStorage` value which moves the button itself jumps; hold it in `@State` and save in `onChange`, and give the button's label its own `.animation(_:value:)`.

**Playback and data**
- **The audio tap's process callback runs on the real-time thread:** no allocation, logging, Swift concurrency or waiting on locks (`SampleBuffer.write` uses `withLockIfAvailable`). Attach a tap before an item plays (setting `audioMix` on a playing item clicks); C callbacks reach state only through `clientInfo`; analyse on the main thread.
- **Callbacks that framework code calls off the main thread must be created in a `nonisolated` context** (a closure in `@MainActor` code inherits its isolation and traps): `NowPlayingController.makeArtwork`, `AudioTap.makeCallbacks`, `SystemVolume.observe`, `AudioPlayer.seekCompletion`.
- **One AirPlay picker, never more:** each `AVRoutePickerView` attaches a fresh output context and drops the route. `OutputRoute` holds the only one; `RoutePicker` is a slot. On the Mac, volume controls disable while `OutputRoute.isExternal` (read from the picker icon's `.active` colour; `isExternalPlaybackActive` is video-only).
- **Space for play/pause** is a fallback at the end of the responder chain (`SpaceBarMonitor`'s `SpaceCatcher`), so fields and focused buttons get Space first; while an AppKit list has focus a monitor takes it (type-select swallowed it), and `SearchFocusMonitor` ends search-field editing on Return or a click outside.
- **Launch shows a saved library, then reads the real one** (~4 s for 20k songs). `LibraryCache` (JSON in Caches) first; covers from `ArtworkDiskCache` (HEIC, named by `ArtworkLabel` so a changed cover never reads stale); each read diffs labels and `ArtworkCache.invalidate` bumps `revision`. A read that changed nothing keeps the snapshot. Changing `Track`'s shape means bumping `LibraryCache.schema`.
- **Smart-filter rules are compiled once per step**, and text fields are folded once per library version (`FoldedText`, shared by a page's elements, evaluated in parallel); per-song `range(of:options:)` cost ~85 ms per element. New text fields go in `SmartFilterEngine.text`, folded with `SearchText.fold`.
- **Persisted Codable models must keep decoding** (`pages.json`): new `SmartFilter` properties need `decodeIfPresent` or an optional; `ElementAppearance` decodes every field with `decodeIfPresent`.
- **Settings file** (`SettingsArchive`): page definitions plus `SettingsArchive.preferenceKeys`; new user-facing `@AppStorage` settings belong in that list (not window state, secrets or history).
- **Swift 6.2 IRGen crash:** a `@MainActor` method reference as a `Binding` setter; wrap it: `set: { someMethod($0) }`.
- SF Symbol names aren't checked at compile time; a typo renders blank and logs "No symbol named …".

**iPad and iPhone**
- **Never switch the whole window's Light/Dark for a cover:** a flip while a page zoomed or slid in turned the page underneath white. Cover pages take the cover's scheme themselves; the status bar follows `toolbarColorScheme`, which iOS ignores while the bar's background is hidden (cover pages use a visible clear one) and reads only as the page appears (`refreshesStatusBar(for:)` nudges it when colours arrive late). Now Playing sets `preferredColorScheme` only while open.
- **Hiding the back button turns off the back swipe:** `coverPageChrome` restores it (`SwipeBackEnabler`). Album and artist pages use the zoom transition (`zoomSource`/`zoomDestination`, swipe down to close); `HeroTransition.flies` is false on iOS. A page zooming away briefly holds touches; working around it with hit-testing added lag.
- **A phone's sidebar is a drawer** (`SidebarDrawer`), not the collapsed split view, whose list cleared its selection on going back ("No pages", swipes bounced).
- **Synced songs aren't files:** `assetURL` is `ipod-library://…` (guard file checks with `isFileURL`). MediaPlayer gives no size, bitrate or kind (hide what depends on them), and `releaseDate` is empty: the year is the undocumented `"year"` property (`MediaLibrarySource.year(of:)`).
- **Forms:** two plain buttons in one row share its tap (use `.buttonStyle(.borderless)`); give each `fileImporter`/`fileExporter` its own view.
- **Tiles wait briefly for cover colours** (`openWhenReady`, `colourWait`, shorter on iOS with no hover to work them out ahead); every tile that opens a page goes through it. The album cover's viewer ignores taps in a page's first half second (a repeated tap opened it).
- **Device installs** build for the connected device by UDID (a free Apple ID's profile lists only devices built for); `devicectl … process launch` needs `--` before app arguments. The Mac target forces `DEVELOPMENT_TEAM` empty.
