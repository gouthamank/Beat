# Beat

Native macOS music player on top of the stock Music app's library. It reads the library read-only, shows album art, and plays local files itself. The headline feature is a **sidebar of folders and pages**. Each page holds elements, and each element owns a **smart filter** (a Filter → Sort → Limit pipeline) plus its own appearance. The UI uses Liquid Glass on macOS 26 and frosted materials on macOS 15.

See `ARCHITECTURE.md` for how the pieces fit together.

## Hard rules
- **Never write to the Music library.** Reading goes through `iTunesLibrary.framework`, which is read-only by design. Beat's own play counts and skips go to `PlayHistoryStore` (`~/Library/Application Support/Beat/history.json`), never to Music.
- **Liquid Glass branching lives only in `Beat/DesignSystem/Glass.swift`.** Views call `beatGlass(in:)`, `beatGlassButtonStyle()` and `BeatGlassContainer`, and never use `#available(macOS 26, *)` directly. Deployment target is macOS 15.0 and the dev machine runs 15.x, so every glass call needs a material fallback.
- **Online features are opt-in only.** Lyrics (`lyrics.online`), artist info from Discogs (`artistInfo.online`, plus the user's own token in the Keychain) and Last.fm scrobbling (`lastfm.enabled`, session key in the Keychain) are off by default; with them off, Beat makes no network requests. Lyrics are never written back to files or to Music.
- **No secrets in the repo.** The Last.fm API key and secret come from the git-ignored `Config/Secrets.xcconfig` (included by `Config/Beat.xcconfig`, surfaced as `LastFMAPIKey`/`LastFMSharedSecret` in Info.plist). User credentials (Discogs token, Last.fm session) live in the Keychain.
- **Local, DRM-free files only.** Apple Music streaming and cloud-only tracks are out of scope; tracks without a file `location` are skipped at load.

## Build and test
The Xcode project is generated by XcodeGen and is not checked in. Edit `project.yml`, never the `.xcodeproj`.

```sh
xcodegen generate                                         # after adding/removing files or editing project.yml
export DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer   # xcode-select points at the Command Line Tools
xcodebuild -project Beat.xcodeproj -scheme Beat -derivedDataPath build build
xcodebuild -project Beat.xcodeproj -scheme Beat -derivedDataPath build test
open build/Build/Products/Debug/Beat.app
```

The `Makefile` wraps these for the user: `make install` (Release build into `/Applications`, quitting and relaunching Beat), `make build`, `make test`, `make clean`. The no-CLI-builds rule below still applies to Claude.

- Signing uses a self-signed certificate, "Beat Local Signing", in the user's login keychain (no Apple developer identity). One stable identity keeps the Media & Apple Music and Keychain permissions across rebuilds; ad-hoc signing (`"-"`) re-prompted after every build. On a new Mac, import or recreate the certificate (Keychain Access ▸ Certificate Assistant ▸ Create a Certificate, Code Signing) before building.
- The app icon PNGs in `Beat/Assets.xcassets/AppIcon.appiconset` are generated: change `Design/AppIcon/render.swift` (keep `AppIcon.svg` in sync), then run `swift Design/AppIcon/render.swift` from the repo root. `Design/AppIcon/Foreground.svg` is the Icon Composer layer for a macOS 26 `.icon`. If the Dock or About panel shows a stale or blank icon after a change, macOS cached the old one: run `lsregister -f` (in LaunchServices.framework/Support) on the built app, quit Beat, `killall Dock`, relaunch.
- Requires Xcode 26.x (macOS 26 SDK, Swift 6.2) for the glass APIs. Language mode is Swift 6 with strict concurrency.
- The real library is large (about 20k songs and 3k albums). Keep work on the main actor cheap and run evaluation and decoding off it.

## Working agreements
- **Verification is manual, by the user.** The user builds, runs and tests from Xcode, so never run `xcodebuild` or `xcodegen` yourself. After each change, say whether files were added or removed (they then run `xcodegen generate`) and which tests cover it, then give a plain-English, numbered verification script (what to click, what they should see). Don't drive the app with AppleScript UI scripting to verify. Screenshots are fine for quick sanity checks while debugging a reported issue.
- Pure logic gets unit tests. That means `QueueState`, `SmartFilterEngine`, `LibrarySnapshot.build`, `PageTree`, `PageStore` persistence, `CustomField` extraction, `ArtworkPalette` picking, `LRC`/`LyricsResolver`, `SongsQuery`, `SpectrumAnalyzer`/`Smoother`, `LibraryWatcher.isRelevant`, `LibraryPage` visibility storage, `AlbumSongsLayout`, `GridNavigation`, `ElementPaging` (fill across/down), `TimelineYears`, `CoverFlowGeometry`, `SettingsArchive`, the `EditableFilter` conversions, `ScrobbleQueue`/`LastFMRequest` (signing, batches, answers), `MixChapters` (tracklist vs lyrics), `BarTint`, `SceneColours` and `CoverBounce`. Use the `Track.fixture(...)` helper in `BeatTests/LibrarySnapshotTests.swift`, `SeededRNG` for anything random, and inject `now`/`calendar` into `PreparedLibrary` for date rules.
- Match existing style: `@MainActor @Observable` stores injected with `.environment(...)`, small focused views, terse doc comments that explain *why*.

## Gotchas (learned the hard way)
- **Pushed `NavigationStack` pages cover overlays on the stack.** On macOS each pushed destination is layered above anything attached to the `NavigationStack`. So the now-playing bar is one `WindowNowPlayingBar` overlay on the `NavigationSplitView` (above pushed pages, like `HeroOverlay`), placed over the page column from `navigator.detailColumnFrame`, which `DetailColumnReader` measures. Pages only apply `.nowPlayingBarSpace()` (bottom content margin, swipe-back chevron) on the root page and every `navigationDestination`. Don't move the bar onto the stack or back onto pages.
- **Pushed pages need an opaque background.** A pushed page that draws none (the genre and See All grids) let the page underneath show through once an album page had been pushed over it and popped, so `RootView` puts the window background behind every `navigationDestination`.
- **Back navigation stays on the system `NavigationStack`.** `AppNavigator.path` is a typed `[Route]` so a pop can tell an album page left; its didSet starts `HeroTransition.returnFlight`, which flies the cover back to the tile it came from (tiles register via `registerTile`) or fades. ⌘[, the trackpad swipe (`SwipeBackMonitor`, back only, chevron instead of a finger-following page) and re-clicking the selected sidebar item (`SidebarReclickMonitor` → `reselect()`) all go through `goBack()`/`path`. A custom finger-following stack is parked in `TODO.md`.
- **Navigation rule:** details nest inside the page you started from, on Library and custom pages alike; a route already in the trail is returned to instead of pushed again (`AppNavigator.opening(_:on:)`). Open albums, artists and genres only through `AppNavigator.openAlbum/openArtist/openGenre` (never `NavigationLink(value:)` or `path.append`), and change `path` once per navigation. Each sidebar page keeps its path, search (`navigator.search(_:else:)`) and scroll (`.remembersScroll(_:)`) for the session.
- **Swift 6.2 compiler crash:** passing a `@MainActor` method reference as a `Binding` setter (`Binding(get: …, set: someMethod)`) crashes IRGen. Wrap it in a closure: `set: { someMethod($0) }`.
- **Callbacks that framework code calls off the main thread must be created in a `nonisolated` context.** A closure written inside a `@MainActor` function inherits that isolation, and Swift's executor check traps when it runs elsewhere. Seen with `MPMediaItemArtwork`'s request handler (`NowPlayingController.makeArtwork`) and the audio tap's C callbacks (`AudioTap.makeCallbacks`).
- **Space for play/pause** is a fallback at the end of each window's responder chain (`SpaceBarMonitor` attaches a `SpaceCatcher` responder), not a menu shortcut or event monitor, so text fields and the keyboard-focused button get Space first. Two exceptions: while an AppKit list has focus (the sidebar after a click, the Songs table) a monitor takes Space, because a list's type-select swallowed it silently; and `SearchFocusMonitor` ends search-field editing on Return or a click outside the field, so focus doesn't linger there. SwiftUI's first responder is always its internal `KeyViewProxy` and accessibility reports only a group, so "is a button focused?" can't be checked up front.
- **Persisted Codable models:** everything in `pages.json` must keep decoding. Adding a non-optional stored property to `SmartFilter` breaks it, so add a custom `init(from:)` with `decodeIfPresent` or make the property optional. `ElementAppearance` already decodes every field with `decodeIfPresent`; keep it that way for new settings.
- **Sidebar tree rule:** folders and pages mix freely at any level; only pages are leaves. Don't add features that assume structure (e.g. "top level is folders").
- **Selectable `List` rows on macOS must stay plain.** `.draggable`, `.dropDestination` or `.popover` on a row with a selection tag swallows the click, and the row stops selecting. Use `.itemProvider` for drag, put drop targets only on non-selectable rows (folders), and present popovers/sheets from the list level. Apply `.tag` last.
- **No drop insertion in nested sidebar levels.** `ForEach.dropDestination` inside nested `DisclosureGroup`s traps in SwiftUI's `OutlineListCoordinator.performDropInsertion`. The page tree is rendered as one flat `ForEach` (`SidebarRow.visible`), and moves are applied in a `Task` after the drop callback returns.
- **Cross-hierarchy transitions** (album and artist zoom via `HeroSubject`, Now Playing morph) measure views with `FrameProbe` in window coordinates and draw in an overlay on the `NavigationSplitView`. `matchedGeometryEffect` and `.global` don't reach across macOS's separately hosted columns and pushed pages.
- **`Table` cells don't inherit `@Observable` environment objects** on macOS (rows are AppKit-hosted). A cell view that reads `@Environment(SomeStore.self)` traps with "No Observable object of type … found". Read the store in the table's parent view and pass it in with `.environment(store)` on the cell content (see `SongsTableView.titleCell`).
- **The audio tap's process callback runs on the real-time audio thread.** No allocation, no logging, no Swift concurrency, and no waiting on locks: `SampleBuffer.write` uses `withLockIfAvailable` and drops the buffer if the main thread holds the lock. Likewise, attach a tap before an item starts playing (`AudioPlayer` waits for it); setting `audioMix` on a playing item rebuilds its render chain and clicks. The C callbacks reach state only through the tap's storage pointer (`clientInfo`, retained at creation and released in finalize). Do analysis on the main thread, never in the callback.
- **Library ▸ Songs is an AppKit `NSTableView`** (`AlbumSongsTable`), not a SwiftUI stack: a `LazyVStack` of ~3k album blocks spent most of its time in layout and hover hit-testing. Rows come from `AlbumSongsLayout` (artist group rows that float, album spacer rows sized to fit the cover). Covers are a small reused pool of hosted `CoverBlock`s (plain covers: a click shows the full-window viewer, nothing else) placed behind the rows for on-screen albums only; `SongRowView.hitTest` passes cover-column clicks through to them. Don't add per-row SwiftUI hover or gestures back.
- **One AirPlay picker, never more.** Every `AVRoutePickerView` given a player attaches a fresh output context, which drops the AirPlay route. `OutputRoute` (owned by `PlaybackQueue`) holds the only picker; `RoutePicker` is just a slot it moves into. Don't create pickers per view. macOS has no public API for AirPlay volume, so the volume slider, mute and ⌘↑/↓ disable while `OutputRoute.isExternal`. That is read from the picker icon's `.active` colour, because `isExternalPlaybackActive` is for video only and stays false for audio AirPlay. When the Mac's whole output is an AirPlay speaker, Beat's volume does apply and `isExternal` stays false.
- **The window's minimum width goes on the detail column, not the root view.** A `.frame(minWidth:)` on the window's root (`BeatApp`) cuts the sidebar's expand animation short on macOS 15: the page slides halfway, then snaps, and the toolbar briefly overflows (`»`). Only `minHeight` stays on the root; `RootView` puts `minWidth` (`detailMinWidth`, 680) on the detail, and again on every `navigationDestination`: pushed pages are hosted separately and set the window minimum themselves, so without it an album page let the window shrink below the root page underneath, which overflowed and shifted the column. Reproduced in a bare `NavigationSplitView`.
- **`$appStorage.animation(_:)` doesn't animate.** The write reaches the view without the binding's animation, so a toggle bound to an `@AppStorage` setting just pops. Use `.animation(_:value:)` keyed on the setting instead (see `AlbumsLibraryView`). Even then, a button that toggles an `@AppStorage` value which moves that same button jumps to its new place while everything else slides; hold such a setting in `@State` and save it in `onChange`. Separately, a clicked button passes the change to its own label without the animation, so give the label its own `.animation(_:value:)` (Now Playing's lyrics toggle needed both).
- **Stacks write back on teardown.** A `NavigationStack` being torn down (after `.id(selection)` changes) clears its path through its binding; `AppNavigator.pathBinding(for:)` ignores writes from a stack whose sidebar item is no longer selected.
- **Cover colours have one owner: `CoverTint`** (`navigator.coverTint`). It derives the front page's colours from `AppNavigator.path` (album → its cover; artist → `ArtistPageContent.featuredAlbumID`), waits a short settle, and applies only the latest answer. Album/artist page backgrounds and text, the sidebar, the window's light/dark and the now-playing bar all read `coverTint.current` (pages only when `current.route` is theirs). Views never publish or clear colours from `onAppear`/`onDisappear`; that raced.
- **`preferredColorScheme(nil)` doesn't restore the system appearance** on macOS once a window was given a scheme; it stays in that scheme. `RootView` passes the cover's scheme or, otherwise, the system's (read from `AppleInterfaceStyle`, updated on `AppleInterfaceThemeChangedNotification`), never nil.
- **A `FrameProbe` on a view that swaps its content after appearing gets released** and never rebuilt, so a zoom from it silently doesn't start. Artist art therefore comes from `ArtistImages` (one synchronous answer per artist: downloaded photo or mosaic), and every copy (tile, header, flying copy) matches. A first download does swap mosaic → photo, so `ArtistArtwork` keeps one fixed outer view and swaps only inside its overlay; never put a probed view's branches in a `Group` (its modifiers, the probe included, apply per branch).
- **Keyboard navigation in collections** (`KeyboardGrid.swift`): a grid, shelf or list is one Tab stop (`.keyboardGrid(count:layout:)`, focusable for keyboard only), items mark themselves with `.keyboardGridItem(i)` and read `\.gridItem` to draw `keyboardHighlight` and to open themselves when `activation` changes. Tiles aren't Tab stops themselves (Buttons inside get `.focusable(false)`). Apply `.keyboardGrid` outside `.remembersScroll`/`.tracksScrolling`: it wraps the scroll view in a `ScrollViewReader`. Pass `id:` (the item's `ForEach` id) whenever items aren't identified by position: without it each item gets `.id(position)`, which overrides the `ForEach` identity, and the Albums grid kept stale tiles after a search.
- **Settings file** (`SettingsArchive`, Settings ▸ General ▸ Export/Import): page definitions plus an allowlist of preferences (`SettingsArchive.preferenceKeys`); import replaces both. A new user-facing `@AppStorage` setting belongs in that list; window state, secrets (the Discogs token) and play history don't.
- **Editable lists bind rows by id, not `ForEach($array)`.** A row being deleted (and animating out) can still write through its binding, e.g. a number field committing on focus loss; a position-based binding then indexes past the end and traps. Use `ForEach(array) { item in … $array.element(item) }` (`Binding.element(_:)` in `RuleEditors.swift`).
- **No SwiftUI `.shadow` or live `.blur` on anything that scrolls or animates.** `.shadow` shadows everything in the view (every glyph of a track list) and is redrawn each frame it moves; on the album page it cost more than every other effect together. Use `ShapeShadow(shape:opacity:radius:y:)` (`Glass.swift`), which Core Animation draws from the outline and eases inside SwiftUI animations. Big blurs are rendered once into an image (`BackdropImages`), and constant animations run on Core Animation layers (`PlayingIndicator`), not a `TimelineView` that re-renders the page around them.
- **Playback colour comes from `\.playbackAccent`, never `.accentColor`.** Progress, playing markers in lists, and active shuffle/repeat/queue/lyrics/volume take the playing cover's colour (`PlaybackAccent` in `RootView`, made readable by `BarTint.readable`; Now Playing overrides it with its palette). Everything not about playback keeps the system accent. AppKit-hosted table cells don't get the environment: read it in the parent and pass it in.
- SF Symbol names aren't checked at compile time. A typo renders blank and logs "No symbol named …" in the console.
